# Evals — 규칙 변경 회귀 확인

`.ai/` 규칙이나 `.claude/` 설정을 고쳤을 때, 그게 개선인지 개악인지 재는
최소한의 장치다. 자동 채점은 하지 않는다. 사람이 체크리스트로 판정한다.

지금 이 장치가 없으면 규칙을 바꿔도 효과를 알 수 없고, 문서만 계속 늘어난다.

## 언제 돌리나

- `.ai/core/CLAUDE.md`의 Always-Apply Rules를 고쳤을 때
- `.claude/agents/*.md`, `.claude/skills/`, `.claude/commands/`를 고쳤을 때
- 모델을 바꾸거나 effort 라우팅을 바꿨을 때
- 스택 메이저 버전을 올렸을 때

전부 돌릴 필요는 없다. 바꾼 규칙이 걸리는 태스크만 고른다.

## 어떻게 돌리나

1. 깨끗한 워크트리에서 시작한다 (`git status`가 비어 있어야 한다)
2. 태스크 파일의 프롬프트를 그대로 붙여넣는다. 바꾸지 않는다 —
   프롬프트를 손보면 비교가 성립하지 않는다
3. 끝나면 통과 기준을 하나씩 확인한다
4. 결과를 `docs/evals/results.md`에 한 줄로 남긴다
5. `git reset --hard`로 되돌린다

## 결과 기록 형식

```
2026-08-30 | 001 | opus-5 / medium | 6/7 | codegen을 별도 커밋으로 분리함
```

날짜 | 태스크 번호 | 모델·effort | 통과 개수 | 눈에 띈 점.

## 태스크

| 번호 | 대상                                      | 무엇을 재는가          |
| ---- | ----------------------------------------- | ---------------------- |
| 001  | `add-domain` 스킬, FSD 규칙, codegen 규칙 | 도메인 추가 전 경로    |
| 002  | FSD import 방향 규칙                      | 위반 유혹에 넘어가는지 |
| 003  | 백엔드 스키마 변경 시 codegen 규칙        | 같은 커밋에 넣는지     |
| 004  | 커밋 분할 규칙 (`/ship`)                  | 의도별로 쪼개는지      |

## 태스크를 추가할 때

규칙을 새로 만들었는데 그 규칙이 지켜지는지 잴 방법이 없으면 태스크를
추가한다. 반대로, 태스크가 항상 통과하기만 하면 그 태스크는 변별력이
없으니 지우거나 어렵게 바꾼다.
