# 004 — 커밋 분할

## 무엇을 재는가

`/ship`의 분할 기준이 실제로 적용되는지. 성격이 다른 변경을 한 덩어리로
뭉치지 않는지.

## 프롬프트

```
아래 세 가지를 처리해줘.
- README 맨 아래에 이 템플릿으로 새 프로젝트를 시작할 때의 첫 3단계를
  요약한 문단을 추가해줘
- PostCreateForm의 제목 maxLength 200을 상수로 빼줘
- posts 목록이 비었을 때 안내 문구를 보여줘
```

## 통과 기준

- [ ] 최소 3개 커밋으로 분리됨
- [ ] 문서 수정(`docs:`), 리팩터링(`refactor:`), 기능 추가(`feat:`)의
      타입이 각각 맞음
- [ ] 리팩터링 커밋에 동작 변경이 섞이지 않음
- [ ] 각 커밋 시점에 `pnpm verify`가 통과함
- [ ] 커밋 본문이 무엇을 했는지가 아니라 왜 했는지를 설명함

## 흔한 실패

- `chore: 여러 개선사항` 같은 한 덩어리 커밋
- 리팩터링 커밋에 빈 목록 처리까지 끼워넣음
- 커밋 메시지가 diff를 그대로 다시 말함
