# 008. 인증 — 세션 쿠키와 기기 로컬 우선

날짜: 2026-09-17
상태: Accepted

## 배경 (Context)

마이페이지가 저장한 장소, 방문 스탬프, 프로필, 알림 설정을 다룬다. 디자인의
로그아웃 상태 문구가 로그인의 값어치를 명시한다 — "저장한 장소와 스탬프가
기기 간에 그대로 남습니다". 즉 인증의 목적은 접근 제어가 아니라 동기화다.

제약이 두 가지 있다.

첫째, 인증 화면의 디자인 파일이 없다. 네비게이션이 `./Gangneung Auth.dc.html`을
가리키는데 그 파일이 존재하지 않는다. 다만 무엇을 받아야 하는지는 이 디자인
파일에서 복원된다:

- `profileFields` — 이름(닉네임), 이메일, 연락처, 거주 지역, 여행 성향
- `policies[1]` 개인정보 처리방침 — "수집 항목: 이름(닉네임), 이메일, 연락처,
  저장한 장소 및 방문 스탬프 기록", "보유 기간: 회원 탈퇴 시 즉시 파기"
- `noti` — 날씨/축제/코스/긴급/마케팅 5종, 마케팅만 기본 꺼짐
- 로그인 상태의 "비밀번호 변경 · 계정 관리" 링크 → 소셜 전용이 아닌 비밀번호 인증

둘째, 디자인에서 `signedIn`은 하드코딩된 `false`이고 이를 바꾸는 코드가 없다.
로그인은 장식이고, 스탬프·저장·알림·공지 등 나머지 기능은 전부 로그인과
무관하게 동작한다.

## 선택지 (Options)

### 가. 세션 방식

1. JWT (무상태)
   - 장점: 서버에 세션 저장소가 없어도 된다. 수평 확장이 쉽다
   - 단점: 무효화가 어렵다. 로그아웃·비밀번호 변경·탈퇴에서 즉시 끊으려면
     결국 블록리스트를 둬야 하고, 그러면 무상태의 이점이 사라진다.
     "탈퇴 시 즉시 파기"를 약속한 처리방침과 어긋날 여지도 있다

2. 서버 세션 + httpOnly 쿠키
   - 장점: 무효화가 한 행 삭제다. 토큰이 JS에 노출되지 않아 XSS로 탈취되지
     않는다. 구현이 단순하다
   - 단점: 세션 테이블 조회가 요청마다 붙는다. 다중 인스턴스면 DB를 공유해야 한다

### 나. 로그인 전 데이터

1. 로그인해야 저장·스탬프를 쓸 수 있게 한다
   - 장점: 데이터 경로가 하나다
   - 단점: 디자인이 그렇지 않다. 관광 앱에서 첫 방문자에게 회원가입을 요구하면
     이탈한다. 스탬프는 현장에서 즉흥적으로 찍는 기능이다

2. 기기 로컬로 먼저 동작하고, 로그인하면 서버로 올린다
   - 장점: 디자인과 맞고 첫 사용 장벽이 없다. 로그인의 값어치가 "동기화"로
     분명해진다
   - 단점: 병합 규칙이 필요하다

## 결정 (Decision)

가-2(서버 세션 + httpOnly 쿠키)와 나-2(기기 로컬 우선)를 선택한다.

### 세션

- `users` — 이메일 unique, 비밀번호 해시, 닉네임, 연락처, 거주 지역, 여행 성향
- `sessions` — 불투명 토큰의 해시, 사용자, 만료 시각
- 쿠키는 `httpOnly`, `SameSite=Lax`, 운영에서 `Secure`. 이름은 `ongangreung_session`
- 토큰은 `secrets.token_urlsafe(32)`로 만들고 **해시해서 저장한다**. DB가
  유출돼도 그대로 세션을 탈취할 수 없다. 비밀번호와 같은 이유다
- 비밀번호 해시는 argon2 (`argon2-cffi`). PHC 우승 알고리즘이고 파라미터
  기본값이 안전한 쪽이다

> CAUTION: `SameSite=Lax`는 GET 외 요청의 크로스 사이트 전송을 막지만 CSRF를
> 완전히 없애지는 않는다. 상태를 바꾸는 요청은 전부 POST로 두고, 프론트가
> 다른 오리진에 놓이면 그때 CSRF 토큰을 추가한다.

### 화면

디자인이 없으므로 로그인·회원가입 화면은 앱의 시각 언어로 새로 짠다. 받는
항목과 동의 문구는 위에서 복원한 그대로 쓴다 — 마케팅 수신만 기본 꺼짐으로
두는 것은 국내 광고성 정보 수신 동의 관행에 맞는다.

### 로그인 전 데이터

저장·스탬프·알림 설정은 로그아웃 상태에서도 동작하며 브라우저에 보관한다.
로그인하면 서버에 올리고, 충돌은 **합집합**으로 푼다 — 저장과 스탬프는
"했다"가 "안 했다"보다 정보량이 많고, 사용자가 기기에서 한 일을 로그인
때문에 잃으면 안 된다.

## 결과 (Consequences)

- 긍정적:
  - 로그아웃·탈퇴에서 세션이 즉시 끊긴다. 처리방침의 "즉시 파기"를 지킬 수 있다
  - 토큰이 JS에서 보이지 않는다
  - 회원가입 없이 앱 전체를 쓸 수 있어 첫 사용 장벽이 없다
- 부정적:
  - 요청마다 세션 조회가 붙는다. 캐시가 필요해지면 그때 넣는다
  - 기기 로컬과 서버 두 경로를 유지해야 한다
  - 인증 화면이 디자인 검수를 받지 않은 상태로 남는다. 디자인 파일이 나오면
    맞춰야 한다
- 향후 고려사항:
  - 비밀번호 재설정(이메일 발송)은 이번 범위 밖이다. 메일 발송 기반이 없다
  - 소셜 로그인도 범위 밖이다. 디자인에 provider 힌트가 없다
  - 프론트를 다른 오리진에 두면 CSRF 토큰과 `SameSite=None; Secure`가 필요하다
