# 공공데이터 API 지도 — 기능별 연동 대상

<!-- 한국어 요약: 온강릉의 각 기능이 어느 공공데이터 API를 쓰는지, 어떤 것이 이미 연결됐고 어떤 것이 남았는지 정리합니다. -->

> 이 파일이 외부 API 연동의 단일 소스다. 새 기능을 붙이기 전에 여기서 출처를
> 먼저 정하고, 연동 구조는 `docs/adr/007-public-data-integration-layer.md`를 따른다.

---

## 1. 공통 규약

공공데이터포털(data.go.kr)의 API는 기관이 달라도 규약이 같다. 그래서
`app/integrations/publicdata/client.py` 하나가 아래를 전부 처리하고, 기관별
레이어는 파라미터와 응답 스키마만 정의한다.

| 항목      | 값                                                                                          |
| --------- | ------------------------------------------------------------------------------------------- |
| 인증      | `serviceKey` 쿼리 파라미터 (기관 무관, 포털 계정당 1개)                                     |
| 응답 형식 | `_type=json` (미지정 시 XML)                                                                |
| 페이징    | `numOfRows`, `pageNo`                                                                       |
| 응답 봉투 | `response.header.resultCode` / `resultMsg`, `response.body.items.item[]`, `body.totalCount` |
| 성공 코드 | `resultCode == "0000"`                                                                      |

> CAUTION: `resultCode`가 `0000`이 아니어도 HTTP 200으로 내려온다. 상태 코드만
> 보면 실패를 놓친다. 봉투의 `resultCode`를 반드시 확인한다.

> CAUTION: 개발계정 트래픽은 1,000건/일이다. 전체 적재를 반복 실행하면 즉시
> 고갈된다. `--dry-run`과 페이지 제한을 기본값으로 둔다.

키는 `.env`에만 두고 `app/core/config.py`를 통해서만 읽는다. `os.environ` 직접
접근과 소스 하드코딩은 금지다 (`.ai/rules/REVIEW.md`).

## 2. 기능 → API 지도

상태 표기: `연결됨` = 클라이언트·적재·테스트까지 있음, `설계됨` = 구조만 잡힘,
`예정` = 아직 손대지 않음.

### 관광 콘텐츠 — 한국관광공사 TourAPI

베이스 `http://apis.data.go.kr/B551011/`. 구 `KorService1`은 은퇴 중이므로 신규는
`2` 접미사를 쓴다.

| 기능 (디자인 위치)                                     | 서비스 · 오퍼레이션                           | 상태   |
| ------------------------------------------------------ | --------------------------------------------- | ------ |
| 관광지 목록 — 홈 레일, 테마 탭, 안내 탭 권역           | `KorService2` / `areaBasedList2`              | 연결됨 |
| 관광지 상세 — 장소 상세 모달 (주소·전화·홈페이지·개요) | `KorService2` / `detailCommon2`               | 연결됨 |
| 운영시간 · 요금 · 주차 — 상세 모달 하단                | `KorService2` / `detailIntro2`                | 설계됨 |
| 추가 사진 — 상세 모달 갤러리                           | `KorService2` / `detailImage2`                | 설계됨 |
| 시군구 코드 조회 (강릉 코드 하드코딩 회피)             | `KorService2` / `areaCode2`                   | 연결됨 |
| 분류 코드 → 자체 카테고리 매핑                         | `KorService2` / `categoryCode2`               | 설계됨 |
| 축제 — 홈 축제 섹션, 안내 탭 축제                      | `KorService2` / `searchFestival2`             | 예정   |
| 위치 기반 주변 검색 — 내 주변 / GPS 스탬프             | `KorService2` / `locationBasedList2`          | 예정   |
| 무장애 여행 — 안내 탭 접근성 경로                      | `KorWithService2` / `detailWithTour2`         | 설계됨 |
| 다국어 콘텐츠 — i18n (EN/JP/CN)                        | `EngService2` / `JpnService2` / `ChsService2` | 설계됨 |
| 관광 사진 — 카드·상세의 "사진 준비 중" 자리            | `PhotoGalleryService1` / `gallerySearchList1` | 설계됨 |
| 연관 관광지 — 상세의 "이어서 보기", AI 코스 후보       | `TarRlteTarService1` / `areaBasedList1`       | 설계됨 |
| 집중률 — 안내 탭 "지금은 성수기입니다"                 | `TatsCnctrRateService` / `tatsCnctrRatedList` | 설계됨 |

기관 루트는 `app/core/config.py`의 `tourapi_root_url` 하나이고, 서비스 경로는
`app/integrations/tourapi/services.py`가 들고 있다. 인증·페이징·봉투는 서비스가
달라도 같으므로 `PublicDataClient`를 그대로 재사용한다.

다국어는 오퍼레이션 이름과 응답 스키마가 국문과 같다. 그래서 언어별 클라이언트를
따로 만들지 않고 `HttpTourApiClient`에 경로만 바꿔 넣는다 (`TourLanguage`).

> CAUTION: 오퍼레이션 이름은 공공데이터포털 문서에서 확인한 것이다. 실제 키로
> 호출해 응답 필드까지 맞춰본 것은 `KorService2`뿐이다. 나머지 다섯은 키를 받은
> 뒤 필드명을 한 번 대조해야 한다 — 특히 사진(`gal*`)과 데이터랩 계열(`rlte*`,
> `cnctr*`)은 표기 규칙이 국문 서비스와 다르다.

> NOTE: 관광 사진은 공공누리 1유형이다. 출처(촬영자)를 함께 보관하고 화면에
> 밝혀야 한다 — `GalleryPhoto.photographer`를 버리지 않는 이유다.

`areaCode=32`가 강원이다. 강릉 `sigunguCode`는 `areaCode2`로 조회해서 쓴다.

> NOTE: `mapx`가 경도(lng), `mapy`가 위도(lat)다. 뒤집기 쉽다.

### 날씨 · 바다 — 기상청

베이스 `http://apis.data.go.kr/1360000/`.

| 기능 (디자인 위치)                              | 서비스 · 오퍼레이션                             | 상태 |
| ----------------------------------------------- | ----------------------------------------------- | ---- |
| 현재 기온 · 체감 — 안내 탭 "오늘의 바다와 하늘" | `VilageFcstInfoService_2.0` / `getUltraSrtNcst` | 예정 |
| 시간별 예보 — `wxHourly` 스트립                 | `VilageFcstInfoService_2.0` / `getUltraSrtFcst` | 예정 |
| 일별 예보 — `wxDaily` 5일                       | `VilageFcstInfoService_2.0` / `getVilageFcst`   | 예정 |
| 파고 · 수온 — `wxSeaRows`                       | 해양 기상 (연안예보)                            | 예정 |

격자 좌표(`nx`/`ny`)가 필요하다. **하드코딩하지 않고** 위경도 → 기상청 격자
변환식(Lambert Conformal Conic)으로 계산한다. 값을 박아두면 지역 확장(속초·동해)
때 막힌다.

> NOTE: 디자인의 날씨 출처 문구가 "기상청 동해중부 연안예보"다. 이는 TourAPI와
> 무관한 **두 번째 기관 연동**이다. 범위 산정에서 자주 누락되는 지점이다.

## 3. 외부 출처가 없는 데이터

디자인 콘텐츠 중 상당량은 공공 API에 대응물이 없다. 이것을 API로 채우려 하면
안 된다.

| 데이터                                                   | 성격                                                      |
| -------------------------------------------------------- | --------------------------------------------------------- |
| 관광지 소개 문구 ("하늘, 바다, 호수, 술잔, 그대 눈동자") | 편집 저작물. TourAPI `overview`는 관공서 문체라 대체 불가 |
| 스티커 ("다섯 개의 달", "몽글몽글 뚝배기")               | 편집                                                      |
| 카드 레이아웃 지시 (`span`: wide/tall/std)               | 표현 계층                                                 |
| 권역 분류 (경포권·시내권·대관령권·주문진권·정동진권)     | 우리 고유. TourAPI `sigungu`는 강릉시 하나로 끝난다       |
| 자체 카테고리 (자연·카페·역사·맛집·도심)                 | 우리 고유 택소노미. `contentTypeId`와 1:1이 아니다        |
| 큐레이션 태그 (`['호수','일출','벚꽃']`)                 | 편집. `cat1/2/3` 코드로 환원되지 않는다                   |
| 권역별 교통·숙박·주차·먹거리 서술, 회화 문장, 긴급연락   | 편집 산문                                                 |
| 조회수 · 사진 수                                         | 자체 집계                                                 |

이들은 `spots` 테이블(편집 엔티티)과 프론트 상수가 소유한다. 외부 미러
테이블(`tour_contents`)과 분리된 이유가 이것이다 — ADR 007 참조.

## 4. 키 발급

1. [공공데이터포털](https://www.data.go.kr) 회원가입
2. 위 표의 각 서비스 상세 페이지에서 `활용신청`
   (TourAPI 국문 관광정보는 즉시 승인, 일부는 담당자 승인 필요)
3. 마이페이지 → 오픈API → 인증키에서 일반 인증키(Decoding) 확인
4. `.env`에 기입:

```bash
TOURAPI_SERVICE_KEY=...
KMA_SERVICE_KEY=...       # 기상청 연동 시
TAGO_SERVICE_KEY=...      # 교통 연동 시
```

포털 계정 하나의 인증키가 신청한 모든 서비스에 공통으로 쓰인다. 다만 기관별로
트래픽이 따로 집계되므로 환경변수는 용도별로 나눠 둔다.

> CAUTION: 인코딩 키와 디코딩 키가 따로 제공된다. httpx가 쿼리 파라미터를 다시
> 인코딩하므로 **디코딩 키**를 넣어야 한다. 인코딩 키를 넣으면 이중 인코딩으로
> 인증에 실패한다. 이 서비스에서 가장 흔한 첫 실패 원인이다.
